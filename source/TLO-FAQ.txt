Q: Is TLO a commercial application?
A: No. TLO is freeware.

Q: What does TLO do well?
A: TLO inventories live-music collections, identifies show metadata, creates searchable inventory output, and can tag supported audio files. Results depend on folder names, setlists, tags, database coverage, and optional online lookup sources.

Q: Does TLO inventory absolutely every music file?
A: No. Once TLO identifies a music file, it stops looking. If you have a folder containing both music files and a nested folder with more music files, the nested folder will be ignored. Typically found where an opening act is included in the main folder.

Q: Do I need to define TLOHome before I start?
A: Yes. TLOHome is the root for the applications, databases, logs, setlists, and inventory output. Set it with the TLOHome environment variable or the documented --TLOHome command-line option. The Inventory and Search GUIs resolve it at startup and display it as a read-only label.

Q: What else is required before the first run?
A: A complete installation must contain TLOHome/TLO_DBs/artists.sqlite and TLOHome/TLO_DBs/venues.txt. You also need valid search paths or a valid toBeInventoried.txt file. Optional settings include TLOCurrentStorage for Add Shows and SETLISTFM_API_KEY for setlist.fm lookup.

Q: How difficult is it to set the TLO-related environment variables?
A: The Windows and macOS/Linux/WSL setup steps are described in Sections 4 through 6 of the User Manual.

Q: Can TLO change or remove original material?
A: Yes. Rename Compliantly, Tag in Place, SHN-to-FLAC conversion, and Tag Copy/Delete Original can change or remove original files or folders. Same-partition Copy/Delete Original transfers are directory moves and do not use file-size comparison. Cross-partition Copy/Delete Original transfers recursively copy the complete identified folder tree and verify relative file paths, file sizes, and descendant folder structure before the source is removed. Tag Copy also copies the complete folder tree and verifies the same file and folder structure because it always creates and retains a separate copy. SHN conversion is also verified before removing the source. These operations are intentionally destructive and are not an undo system. Keep an independent backup when preserving pristine source material matters.

Q: What happens if I inventory the same drive again?
A: For a named volume, TLO deterministically replaces, prunes, or appends the affected scope according to whether the new path is the same as, a parent of, a child of, or separate from the stored paths. It does not ask a Skip/Re-inventory question. Blank-volume runs append to the shared blank-volume logs and can create duplicate inventory entries if the same content is scanned again.

Q: Can Rename Compliantly rename my entire collection or search root?
A: No. TLO may aggregate true CD, disc, part, or volume siblings only when every direct music-bearing child under the parent belongs to that one release relationship. If any direct music-bearing sibling is unrelated, the folders remain separate and the broad collection/search parent is never renamed as one show. Text such as v.2 inside a larger descriptive parenthetical does not count as a volume suffix.

Q: Does Artist in Album Tag apply during Full Inventory?
A: Yes. When checked, Full Inventory with Tag in Place, Tag Copy, or Tag Copy/Delete Original writes Album as Artist followed by the resolved date, venue, location, and preserved parentheticals. Add Shows tagging and standalone Tag use the same rule.

Q: Can I see what TLO plans to do before it changes anything?
A: Yes. Full Inventory, Add Shows, and Tag show a Review Operation screen before starting. Every Review Operation dialog reports all main-window checkbox values in the same order. Tag has no duplicated option checkboxes, and Add Shows retains only its action-specific Check for Duplicates checkbox. Both child windows read the current main-window values when an action starts. Dry run is controlled only by the checkbox on the main Inventory window; the Tag and Add Shows windows inherit that current value and do not have their own Dry run checkboxes. With Dry run selected, click Inventory, Tag, Process New Shows, or Process Potential Duplicate/Upgrades. Dry run resolves and displays resulting show names and planned actions. When tagging applies, it lists each applicable audio file with the Artist, Album, Track, and Title values that would be written, plus the title source, planned SHN-to-FLAC target, potential duplicate matches, or reason a file would be skipped. Dry run does not write tags, convert, rename, copy, move, delete, create inventory output, or change TLO logs.

Q: Are trailing folder parentheticals preserved in the resulting show name?
A: Yes. TLO captures trailing parenthetical items before it cleans the folder name for metadata parsing, then restores them after artist, date, venue, and location normalization. For example, Danny Gatton 1994-03-13 Bottom Line NYC (set 2) resolves to Danny Gatton 1994-03-13 Bottom Line New York, NY (set 2). Multiple trailing parentheticals remain in source order without duplicate entries.

Q: Can Compliant and Rename Compliantly be selected together?
A: No. They are mutually exclusive. In the main Inventory window, checking either one automatically unchecks the other. Tag and Add Shows inherit the resulting main-window values. On the inventory, GUI-launcher, and standalone-tagger command lines, using --compliant and --rename-compliantly together produces an argument error.

Q: When does TLO ask for a Tag Copy destination?
A: Checking Tag Copy or Tag Copy/Delete Original only selects the mode. TLO asks for the destination after Inventory is started, including when Dry run is selected. Both dialogs validate the full path and show available storage. Tag Copy always totals the source, copies the complete identified folder tree, and verifies relative file paths, sizes, and descendant folder structure. The copy/delete dialog additionally warns that originals will be removed; same-partition transfers move the complete folder tree with no size totaling or comparison, while cross-partition transfers recursively copy and verify the complete tree before deletion.

Q: When does TLO call a same-named show a copy instead of an alternate?
A: A matching Show or compliant folder name is not enough. Before TLO uses a (copyN) qualifier or folder suffix, it compares the complete recursive trees. The relative folders (including empty folders), relative files, file sizes, and every file's byte contents must all match. TLO uses SHA-256 content comparison after the faster structure and size checks. If anything differs, or a comparison cannot be completed, TLO uses (altN) instead. File timestamps do not matter. A source folder that already carries (copyN) is also rechecked before that qualifier is used in the Show name.

Q: Where are the settings for each run recorded?
A: After you choose Start in Review Operation, TLO appends the action, local date/time, and the same reviewed settings lines to TLOHome/logs/runSettings.log. The file is shared by Full Inventory, Tag, Process New Shows, and Process Potential Duplicate/Upgrades, including Dry runs. Command-line Inventory and Tag use the same log. Choosing Go Back or closing Review Operation does not create an entry.

Q: Where do I find problems after a run?
A: The completion summary includes View Issues and Open Logs. View Issues groups recognizable problems by reason, such as unidentified shows, missing setlists, track-title mismatches, unreadable audio, copy or verification problems, online lookup problems, and other tagging or file errors. Select an issue and use Open Path when TLO has a usable path for it.

Q: Why does the Current Operation activity indicator move slowly?
A: The indeterminate activity indicator moves at one-tenth of its former speed in Inventory, Tag, and Add Shows. This is only a visual animation change; it does not slow inventory, tagging, Add Shows, elapsed-time updates, or worker processing.

Q: Where does TLO store setlist.fm rate-limit information?
A: Build 356 and later store it under TLOHome/logs/setlistfm-state. TLO no longer uses a shared system temporary-directory state file. A worker abandons a blocked reservation after 20 seconds and continues without that lookup.

Q: How do I safely remove duplicate folders?
A: Use tlo-deleteDupes with a fully qualified search path. TLO discovers candidate siblings from exact X/(copyN) families and from matching normalized artist/date names, then compares copies with one another as well as with unsuffixed folders. Folders with the same complete recursive structure, relative file names, and file sizes form a content-equivalence cluster. TLO keeps one folder per identical cluster, preferring an unsuffixed name; if the cluster contains only numbered copies, it keeps the lowest-numbered copy. The other identical cluster members are moved as whole folders into a folder named duplicates at the root of the partition containing the search path. Thus, if X differs from X (copy2) and X (copy3), but copy2 and copy3 match each other, TLO keeps X and copy2 and moves copy3. TLO creates the duplicates folder if needed, never overwrites an existing holding-folder entry, and appends each moved folder's original full path to TLOHome/deletedDirs.txt. When candidate folders differ, TLO records short CSV lines in TLOHome/deleteDupesMismatches.txt using folder name, folder name, and a simple reason such as different number of files, different sub-structure, or 01.flac different sizes.

Q: How can I research what TLO found in the comp and meta logs?
A: In the main Inventory window, click Research and enter an artist followed by a date, a venue, or a date. Research accepts every date form recognized by TLO Inventory, including partial/unknown forms such as xxxx-xx-xx and 202x-xx-xx, textual-month dates, compact dates, slash dates, and supported ranges; a standalone four-digit 19xx/20xx year is also accepted. TLO normalizes the date for matching and returns every matching metadata record plus all correlated comp-log paths. It then continues through every meta*.log and comp*.log line and adds an ALL RELATED RAW LOG LINES section with every directly related occurrence and its log filename/line number; it does not stop at the first occurrence. The standalone tlo-research app performs the same search and writes the same complete result to the console.
